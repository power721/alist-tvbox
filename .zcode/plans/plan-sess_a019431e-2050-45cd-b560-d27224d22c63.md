# 关注直播间功能实现计划

## 方案总览
**关注数据统一存后端**(不采用 spider 本地存储+同步):spider.jar 与后端始终配套,单源数据让所有设备实时生效,省掉一套同步状态机。身份解析与播放记录同步一致:用户名订阅 token → 对应用户;共享订阅 token → 首个管理员。

**TVBox 端交互**(TVBox 无原生"关注"按钮,用标准轨道技巧):
- 详情页追加 **"关注/取消关注"** 播放轨道,点击后 spider 的 playerContent 拦截(id 以 `follow$`/`unfollow$` 开头)→ POST 后端 → 返回 `toast://已关注` 提示(FongMi 播放器支持 toast://,见 https://github.com/FongMi/TV)
- 展示(用户已确认两者都要):**首页推荐列表前插入关注房间**(开播优先)+ **分类列表首位"关注"分类**

## 一、后端 (alist-tvbox)

### 1. 数据层
- `entity/LiveFollow.java`:id(共享 tableGenerator)、uid、platform、roomId、roomName、anchorName、cover、createdTime;唯一约束 (uid, platform, roomId)。Repository `entity/LiveFollowRepository.java`(与 HistoryRepository 同包)
- Flyway Java 迁移 `db/migration/current/V19__LiveFollow.java`,仿 V10 幂等写法(CREATE TABLE IF NOT EXISTS + 唯一索引存在性检查);同步注册到 `META-INF/services/org.flywaydb.core.api.migration.JavaMigration` 和 `config/NativeFlywayMigrationConfig.java`
- DTO:`dto/LiveFollowDto.java`(platform、roomId、roomName、anchorName、cover、live、followedTime)

### 2. `live/service/LiveFollowService.java`
- `resolveUid(token)`:`userService.findByUsername(token)` 命中则该用户,否则首个 ADMIN(镜像 SubscriptionService.playbackTokenForSubscription 的归属逻辑)
- `follow(uid, platform, roomId)`:调平台 `detail(platform$roomId)` 补全房间名/主播/封面后 upsert(取不到则存空值)
- `unfollow(uid, platform, roomId)`
- `list(uid)`:并行调各平台 detail 刷新开播状态与元数据(Caffeine 每房间 2 分钟缓存;开播在前、关注时间倒序;单平台失败降级为已存元数据),输出 MovieList(vod_id=`platform$roomId`,remarks=主播+状态)
- `isFollowed(uid, platform, roomId)`
- 依赖注入 `List<LivePlatform>` 做平台路由,避免与 LiveService 循环依赖

### 3. 接口层
- `LiveController`:
  - `POST /live/{token}/follow`、`POST /live/{token}/unfollow`(JSON body `{platform, roomId}`),先 checkToken 再 resolveUid;`WebSecurityConfiguration` permitAll 列表追加这两条路径(路径含 {token} 通配)
  - `browse()` 拦截 `t=follow` → `liveFollowService.list(uid)`
- `LiveService`:
  - `category()`:首位插入"关注"分类(type_id=`follow`)
  - `home()`:结果前插入关注列表(uid 经 `SubscriptionService.getCurrentToken()` ThreadLocal 解析)
  - `detail()`:平台结果(缓存原始版)返回前**在副本上**追加关注轨道:`vod_play_from += "$$$关注"`、`vod_play_url += "$$$关注$follow$platform$roomId"`;已关注则显示"取消关注"轨道,避免污染 15 分钟缓存
- 管理 API `GET/DELETE /api/live/follows`(仿 PlaybackSyncController.currentUid() 取当前用户,WebSecurityConfiguration 显式授予 ADMIN|USER,否则落入 /api/** 的 ADMIN|CLIENT 规则)

### 4. Native image
- Main.java 已扫描 entity/dto 包,新类无需改扫描列表;`mvn compile` 后运行 `java -cp target/classes cn.har01d.alist_tvbox.Main` 重新生成 reflect-config.json

## 二、spider.jar (CatVodTVSpider)
- `Live.java` 的 `playerContent`:拦截 `follow$`/`unfollow$` 前缀 id → okhttp POST `{api}/live/{token}/follow|unfollow`(仿 PlaybackSyncer.postJson 的 RequestBody JSON 写法,带 X-CLIENT 头)→ 返回 `{"jx":0,"parse":0,"url":"toast://已关注 XXX/已取消关注/操作失败"}`
- 运行 `./build.sh`(gradlew assembleRelease → genJar.sh → 拷贝 spring.jar + spring.md5 回 alist-tvbox/src/main/resources/static/)

## 三、web-ui(用户已确认要管理页)
- 直播页新增"关注管理"入口/页签:关注列表(封面、房间名、主播、平台、开播状态)+ 取消关注按钮,调 `/api/live/follows`
- 现有网页直播浏览会自动获得"关注"分类和详情页关注轨道(走同一 `/live/{token}` 接口,零额外改动)
- `npm run build` + `npm run lint`

## 四、文档与验证
- `docs/` 新增功能说明(接口、轨道约定、身份归属规则)
- 验证:后端 `mvn compile`/`mvn test` + 反射配置再生成;启动后 curl 验证 follow/unfollow/`t=follow`/detail 轨道/category 首位;构建 spider.jar 并确认拷贝;web-ui 构建

需要执行权限:mvn 编译/测试、java Main 生成反射配置、CatVodTVSpider 的 ./build.sh、npm build/lint、本地 curl 验证。
