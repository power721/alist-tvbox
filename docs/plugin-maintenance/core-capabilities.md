# 核心能力补强

本文描述通用机制，不包含真实来源脚本、运行记录或部署环境信息。

## 联网执行与证据归因

- 受管 HTTP 适配覆盖 `requests` 与 `urllib` 常见调用，源内会话在同一任务的多个 Spider 动作之间衔接。Cookie 仍受来源、域名、路径、Secure 和有效期约束，管理员凭据不随别名或普通响应 Cookie 迁移。
- 单个 `evidenceGateway` 配置兼容 TRAWL、FlareSolverr 和 rs-alt。明确挑战才转网关；网关会话与宿主内存中的轻量 Cookie/UA 会话分别管理，普通 HTTP 复用失败有独立诊断，不把网关文档当作媒体原始字节。
- 保留中断前已确认的 HTTP 观察和实际调用编号，缓存命中也关联到本次动作。分类、详情和播放地址错误不会错误归因到其他调用或被单次缓存成功覆盖。
- 网关连接、超时、繁忙、目标 DNS、挑战仍在、宿主缺配置与源码故障分别归因。`Retry-After` 与冷却沿用原时间/请求预算；目标限流不通过换会话规避。

主要路径：`scripts/source_egress.py`、`managed_loader.py`、`evidence_gateway.py`，以及控制面的 `ManagedSourceRuntime`、`RepairDiagnostics`。

## 内容保全与发布门槛

分类存在、条目非空或取到一个播放地址不足以证明内容完整。装载器记录分类、详情、分组及集数快照，平台把候选与同身份的原件证据比较；新增的缺分类、条目或选集损失会阻止成功发布。

详情数量变化允许使用当前完整原页的精确证据协调：保留字段匹配、变换和筛除计数，核对唯一播放链接覆盖、缺失/额外链接和实际详情调用。重复 DOM 不强算重复集数；截断页面、推荐链接或不透明标识不能用于凑数或推断缺集。

发布门槛同时要求冻结必需节点、当前运行身份、内容保全和清理确认。源码修复、候选复验、文件发布与运行生效分别记录，不相互替代。

主要路径：`ManagedLoaderReceipt`、`ManagedResourceEvidence`、`RepairReport`、`AtPublicationService`。

## 可恢复修复与轮数配置

纯网络或宿主配置阻断暂停模型，不把缺少宿主能力当作源代码错误。运行环境恢复后可复验原候选，保留原维修、历史和累计账本；复验不生成新候选或消耗新修复轮次。独立源码故障和内容退化仍按失败处理，不被环境归因掩盖。

模型请求按已配置的接口大小预算打包。较小请求先压缩历史摘要与证据片段，保留原件身份、固定修复目标和省略标记；原文摘要与截短文本摘要分开，不将缺失上下文伪装为完整材料。必要内容仍超限时明确暂停，不扩大预算或截断源码凑请求。

手动修复、维护任务和周期巡检均接受可选 `maxRounds`，缺省为 3。已有维修可以调整总上限，但不能小于已用轮数，活动模型调用或候选进行中不允许修改。保存上限不启动模型、不清空历史；恢复操作仍使用原任务。

已有维修配置接口：

```text
PUT /api/plugin-maintenance/repairs/{id}/round-limit
```

```json
{
  "expectedFaultSha256": "当前维修故障摘要",
  "expectedMaxRounds": 3,
  "maxRounds": 6
}
```

沿用 AT ADMIN 与 CSRF。新建维修/维护请求及巡检 `automaticRepair` 可设置 `maxRounds`；计划变更不覆盖已经投放的任务。新增可空迁移列保留旧冻结策略和追加授权，不重算已用量。

主要路径：`RepairStore`、`ModelClient`、`MaintenanceWorkflowService`、`ProbeScheduleStore`、`RepairController` 及 AT 工作台组件。

## 交付与运维

上游只保留 AT 内置路径。持久发布队列默认增量，替换须显式选择；中文命名、迭代版本、原件和插件配置保护沿用原发布合同。

镜像仍按项目/用途/版本/内容摘要命名。可选 `--retire-stopped-containers` 仅退役项目及用途精确匹配、数据已绑定持久化且不在保留清单中的停止实例；保留当前、回滚和在用运行器，不删数据目录或卷，不全局 prune。详见[镜像生命周期](image-lifecycle.md)。
