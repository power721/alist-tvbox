# 播放消费者脚本取证

## 当前缺口

爱看原维修保留累计 4/4 轮、8/9 必需项和 R01 `PLAYER_URL_INVALID`。RC13 证明 `data.list[0].resData` 内嵌 `[0].url` 与本次返回值相等，但没有证明实际转换逻辑。不能把相等、脚本挑战页或模型解释当成已完成修复。

只读核对 RC14 时发现：NAS 内置测试版没有配置浏览器取证器。本机已有取证器，但不持有该维修记录。本轮直接补内置平台可用的轻量 HTTP 脚本取证，不迁移生产数据或另建维修单。

## 实现

新增管理员接口 `POST /api/plugin-maintenance/repairs/{id}/script-inspection`，沿用维修故障摘要和已观测页面身份。它优先采集与原回执脚本 URL 摘要对应的页面声明，再追踪字面量模块导入，并保存源码片段、偏移、原始响应摘要、截断和完整性状态。相关字段名来自原平台回执，不编造解析接口或算法。

未配置浏览器时，原加强取证入口在请求恢复脚本且未指定动态请求断点的情况下可以选择该操作；模型准备阶段可以为可定位的已观测页面自动采集，重复请求复用冻结回执。`scriptInspectionReady` 与浏览器 `ready` 分开报告，HTTP 采集不冒充浏览器能力。

取证通过现有公共 DNS 固定连接通道执行，独立访客会话，只发 GET；不导入用户凭据、执行 Spider/JavaScript 或求解挑战。页面需与既有完整 GET 的摘要匹配；敏感查询不转发，挑战页、HTML 伪脚本和不完整响应不作为源码。实际声明的跨域公开资源可以采集，不要求网站全部使用同一域名。

沿用 8 次资源读取、18000 字节文本上限。脚本片段优先相关字段和常见转换调用，缺少实际执行证据时 `consumerExecutionVerified`、`transformationVerified` 始终为 false。材料进入普通和加强模型请求，不增加维修轮次、重置历史、修改来源或放宽验收/发布。

## 原页受限后的脚本补取

RC15 在 NAS `18992` 真实采集原播放页，独立访客 HTTP 收到 403 挑战，0 个脚本，未取得实际转换代码。旧页此前成功不代表新的独立会话同样可用。

据此补 RC15.1：`script-inspection` 可以接收少量 `scriptUrls`，但每个完整地址都必须与同一已观测页面下、既有宿主脚本记录的 URL SHA256 精确匹配。不匹配的路径、参数或其他页面脚本在联网前拒绝。即使当前原页访问失败，也可对这些原本就已观测的地址执行一次普通公开 GET；没有猜测 URL、变换域名或规避挑战。

只新增运行 1 项 Python 和 1 项 Java 定向检查，分别覆盖原页挑战时已观测脚本可用的分支、伪造地址拒绝和实际请求装配。没有重跑前一批测试或重构前端。
