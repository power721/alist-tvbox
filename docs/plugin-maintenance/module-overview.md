# AT 内置 AI 源维护

## 目的与交付范围

在 AT 中提供“联网巡检 → 证据诊断 → 模型候选 → 隔离复验 → 平台发布”的维护流程，降低管理员逐个手工修复 Python 爬虫的成本。模型负责提出修改，平台负责执行、验收、持久化和发布；不把模型答复或 HTTP 200 当作修复成功。

唯一管理入口是 AT `/#/maintenance`，直接使用 AT 的 Vue、Element Plus、登录和导航。没有 iframe、独立管理页面、额外管理账号或服务端口。普通 AT 构建保持原行为，仅显式启用 `maintenance-embedded` profile 才接入模块。

## 能力

| 环节 | 平台责任 |
| --- | --- |
| 来源管理 | 内部读取 AT 自定义插件，明文/加密输入识别，来源与版本展示；可选外置 AT 只读取样 |
| 联网巡检 | 手动与周期任务，冻结来源合同和运行身份，展示退化与多轮失败；磁力、资料导航和视频来源分别处理 |
| 取证诊断 | 关联实际分类、详情、取链及媒体调用，区分源码、宿主配置、网络、凭据和挑战阻断 |
| 模型修复 | 配置模型中转站，持久编排候选与调用账本，可恢复暂停/重试，可配置修复总轮数 |
| 隔离复验 | 未知 Python 不在 AT 主 JVM 执行；核对候选、内容保全、运行身份与清理结果 |
| 平台发布 | 持久队列默认增量、显式替换，中文名称与迭代版本，回读发布文件和插件登记；失败候选不得发布 |
| 运维 | 过程查看/导出，冷归档，独立维护迁移历史，按标签管理镜像与显式退役旧停止实例 |

近期增量的机制和接口见[核心能力补强](core-capabilities.md)。豆瓣/TMDB 等复杂助手按明确身份排除自动修复；需要凭据的来源先补凭据。修改后的明文不能冒充原签名加密包，不提供任意站点自动修复保证。

## 结构与审阅顺序

| 层 | 路径与职责 |
| --- | --- |
| 宿主合同 | 前置 #1095：T4 装载身份、参数透传和可选插件写入协调；不依赖维护模块 |
| 隔离运行 | `plugin-maintenance/managed-source/`、`container/`、`scripts/`：受管 Python/HTTP、会话、出站观察与清理协议 |
| 控制面 | `plugin-maintenance/server/src/main/`：Controller → Service → Repository，来源、任务、模型、维修及发布台账 |
| 工作台 | `web-ui/src/maintenance/`：AT 路由内组件，触发和观察服务端任务，不在页面驱动修复轮次 |
| 内置适配 | `plugin-maintenance/at-embedded/`：AT 会话、ADMIN/CSRF、实体/仓储及独立维护迁移历史 |
| 运维文档 | `deployment/`、按需诊断依赖及 `docs/plugin-maintenance/`：安装、合入、数据和交付合同 |

## 合入与兼容边界

先合宿主 #1095，再合模块 #1096。具体构建、配置、数据库及回退步骤见[合入指南](merge-guide.md)。不修改宿主默认构建、登录体系或现有接口合同。

维护与 AT 使用同一 H2 DataSource，维护迁移使用独立的 `maintenance_schema_history`，不占用宿主迁移版本。新增配置列保留旧账本，不重置候选、轮数或费用。旧私有 RC 混合迁移库须按[数据库说明](database-archive.md)导出到新副本，不覆盖旧库或改写历史 SQL。

应用与可信宿主执行包须配套升级，不能只替换 JAR。执行器、网关和按需诊断引擎由管理员配置；Web 不挂载 Docker socket。API 复用 AT ADMIN 会话，写入保留 CSRF，导出不把 token 放入 URL。

代码合入不会自动授权来源外发、模型费用、生产替换或定时任务。网关接入不自动改写生产 AT/T4 的网络实现。H2/JVM 是当前交付路径，其他数据库、Native Image 和客户端连续播放需独立评估。
