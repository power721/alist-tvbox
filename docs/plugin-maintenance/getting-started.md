# 使用 AT 源维护

## 打开工作台

使用 AT 管理员账号登录，在菜单中选择“源维护”，地址为 `/#/maintenance`。本 PR 不提供独立页面、登录账号或服务端口。前后端必须按[内置构建说明](embedded-integration.md)一起启用。

## 首次配置

1. 从折叠的“导入爬虫”抽屉读取 AT 自定义插件或导入明文源码。本机 AT 走内部读取，不需要填写 AT 链接。需要时另配“外置 AT 链接”作只读取样。
2. 在“模型中转站”中填写中转地址、模型名和密钥，启用模型。需要自动修复时另开“自动递交修复候选”并保存连接，无需重启容器。真实模型调用仍须取得当前样本的源码传输授权，不能把示例配置当作可用连接。
3. 接入已授权的同机 T4 隔离执行器，网络取证、复验和清理由平台执行。未取得源站业务响应时不判定爬虫损坏。
4. 对选中爬虫点击“联网巡检”。需要按时间周期运行时，在列表上方“智能巡检”中设置首次时间、周期和巡检后自动修复。

## 取证网关

在“模型与设置 → 隔离执行”中统一配置“取证网关”：一个根地址、一个兼容类型、一个超时。支持 `trawl`、`flaresolverr`、`flaresolverr-rs-alt`，不需要为不同项目分别建立入口。保存后可检查已保存连接；健康只证明服务可达，不代表目标页面取证成功。

脚本取证先直连，明确遇到挑战页后才使用已启用的网关；同一取证任务复用一个网关会话，结束时销毁，不导入或导出 Cookie。TRAWL 使用原生命名会话并可读取浏览器实际捕获的脚本响应；其他适配器的渲染文档不冒充原始 JavaScript 字节。失败记录区分挑战仍存在、网关繁忙、目标 DNS 失败等原因。网关与直连证据分别保留，网络位置显示外置网关，不继承本机固定公网连接的证明。

网关必须由管理员在受控网络内配置。平台校验请求与最终 URL 的公网目标，网关端重定向、子资源和实际连接由网关管理；不将本机 DNS 预检描述为网关端网络隔离，也不额外强制供应商的可选网络模式。

同一设置也供平台隔离爬虫实际联网执行使用：直连确认 HTML 挑战后，宿主以任务和来源域名为界复用网关会话。网关返回有效业务文档、Cookie 及配套 UA 后，宿主可在内存中保留独立 HTTP 会话，后续匹配请求优先走普通 HTTP 出口。Cookie 不进入爬虫 CookieJar、模型、日志或持久文件，也不向网关转交已有账号凭据。普通 403、429、POST、带账号或专用签名头、字节 Range 请求不改道；网关仍是挑战、正文超限、最终地址变化或不可达时保留明确失败记录。直连和网关访问共同消耗原请求/字节/时间预算，任务结束销毁会话；清理未确认不算成功。

网关设置变化会改变脚本取证缓存身份，并在新执行任务开始时冻结；已经开始的执行及其 HTTP 验收子任务沿用原设置。该功能不启动模型调用、不扩充维修轮数、不改变生产发布授权，也不会自动改写生产 AT/T4 的爬虫网络实现。这里返回的是网关渲染 HTML，不认证原始脚本或媒体字节；需要更新宿主执行包后才能在实际执行中使用。

临时网关故障不再永久停用当前来源：忙碌、连接失败、超时、目标 DNS 失败可在冷却到期且原预算允许时，由后续请求恢复；每来源每任务最多恢复两次，不在同一次请求内循环重试。网关 `Retry-After` 控制网关冷却，网关返回的目标站 `429` 则进入原来源限流账本，回传其 `Retry-After`，不通过换会话规避限流。超时或损坏会话须先确认清理，才能重建；创建操作仍可能在途时，“会话不存在”不算终止确认。

日志分别保留故障阶段、冷却剩余时间与预算是否足够，并只投影网关实际返回的 `tier`、`sessionCached`；缺失值显示为未知。命名会话复用不代表每次都执行浏览器。宿主轻量会话限定同一任务、精确 origin、Cookie Path/Secure/有效期，最长 30 分钟；缺少 Cookie 或 UA 时不启用，不跨账号混用。HTTP 响应中的 Cookie 续期仍留在宿主独立状态；拒绝后清除轻量状态，明确挑战可复用原网关会话。`lightweightCookieReuse` 和 `lightweightCounts` 单独记录普通 HTTP 出口的尝试、非挑战 2xx 与拒绝，`cookiesExported=false` 指未向爬虫或证据载荷输出 Cookie，不代表网关从未向可信宿主传递状态。跨出口可能被来源拒绝，不能把网关成功或 HTTP 2xx 单独称作业务修复成功。

匿名任务采用网关会话及配套 UA，同名匿名 Cookie 以网关快照为准；这些名称的后续轮换也留在宿主，不回写源 CookieJar。显式账号凭据、内嵌 Cookie、授权头及专用签名请求不迁移。跳过轻量请求时保留作用域/过期、请求不可复现等有限原因，不输出 Cookie 名称、值或 UA。脚本辅助取证仍优先复用网关浏览器；宿主轻量路径用于隔离爬虫及其受管资源 HTTP 请求，不代表生产 AT/T4 网络已自动改造。

RC16.3 已经平台完成两种网关到宿主普通 HTTP 的[实站轻量复用验收](gateway-cookie-rc16-2026-11-19.md)。这证明两条传输路径复用成功，不证明公网 IP 不同或样本维修成功。

## 修复与交付

列表展示联网结果、当前版本、退化及三轮未修复状态。右侧查看诊断、修复选项和过程日志；修复过程与每次日志可导出分析。

模型生成候选，平台在冻结画像下联网复验。失败或未完成候选不允许发布。成功候选进入持久发布队列，默认增量，也可显式选择替换；中文命名、版本号和替换前原件均由平台交付流程负责。

自动递交、智能巡检和生产发布分别控制。保存模型设置不创建或重启维修任务，也不修改来源授权或发布队列；已启用的调度仍按各自配置运行。自动递交状态持久保存，修改用量限额不会丢失该选择；运行中的模型调用会阻止切换设置，待调用结束后再保存。

纯磁力站不要求直接播放链接；资料导航不应因无播放地址而误判。豆瓣/TMDB复杂助手按明确 ID 排除，不参与自动修复。需要凭据的来源先补凭据，挑战页和网络问题分别归因。

## 当前边界

已支持联网诊断、模型候选、受管复验与持久发布控制，但仍缺真实未知故障无人值守成功到自动发布的完整正向验收。不能将静态通过、HTTP 200、部分节点通过或可打开界面称为源已修复。

不要直接覆盖生产镜像，不在活动 AT 数据库上启动第二个服务。更多说明见[贡献范围](github-review-2026-11-19.md)、[运行器运维](managed-runner-operations.md)和[交付标准](spider-delivery-standard.md)。
