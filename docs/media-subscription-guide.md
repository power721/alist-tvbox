# 追剧订阅使用指南

订阅一部剧,系统自动追更:定时检查资源更新、链接失效自动换源(播放进度不断)、缺集自动从多个分享补齐,还可自动转存到你自己的网盘,彻底告别"收藏夹里的链接全失效"。

## 快速上手

### 1. 创建订阅

管理页 →「追剧」→ 新建订阅:

- **条目链接**(最省事):直接粘贴条目链接,点「解析」自动识别并回填元数据绑定、剧名、季与总集数。支持:
  - 豆瓣 subject、TMDB tv(含 `/season/2` 自动填季)、Bangumi subject、腾讯视频 cover(按 id 直取官方分集);
  - **B 站番剧/动漫/电视剧播放页**(含 ss/ep 的链接;media 页为前端渲染不支持,b23.tv 短链会自动展开)→ 按剧名优先绑定 Bangumi(番剧)或豆瓣;
  - **优酷剧集页 / 爱奇艺剧集页** → 按剧名优先绑定豆瓣(页面为前端渲染解析失败时会有明确提示,改用关键词绑定即可)。
- **剧名 / 搜索词**:展示名与搜索关键词(默认同名)。资源命名与官方名差异大时可填别名。
- **元数据条目**(强烈建议绑定):搜索并选择豆瓣 / TMDB / Bangumi / 官方平台(腾讯/优酷/爱奇艺)条目。绑定后自动获得:
  - 官方总集数与已播集数(缺集检测的权威依据);
  - 播出日程(按"播出后 15 分钟起连查"调度,不用等固定周期);
  - 官方完结状态(达标自动标记完结);
  - 封面与下一季探测。
  - 部分源失败会在搜索框下方提示原因(如 TMDB 需自备可达网络/密钥)。
- **豆瓣增强**(页头「设置」→ 豆瓣 Cookie):登录 movie.douban.com 后复制 Cookie 粘贴保存,豆瓣条目即可解析详情页「又名」(提高搜索结果匹配度),并自动经 IMDb 桥接 TMDB 获得**单集播出时间/已播集数/续订状态/英文名别名**——豆瓣绑定的订阅不用改绑 TMDB 也有完整播出日程。详情页抓取全局限速(≥8 秒/次)+ 24 小时缓存保护账号,留空即关闭。
- **季**:追第几季。同一部剧追多季就每季建一个订阅,互不影响(见常见问题)。
- **资源模式**:
  - **挂载追更**(默认):分享固定挂载在 `/追剧/{订阅}` 路径,失效自动从候选池换源,免网盘账号;
  - **自动转存**:新集自动复制到你自己网盘的 `/追剧/` 目录(见下)。
- **主网盘**(可选):选 1~2 个网盘,巡检优先保证该盘的剧集完整并固定播放线路;清空则跟随全局设置(页头「通知」→ 全局主网盘,见「通知与维护」)。
- **筛选条件**:盘类型偏好(可排序)、清晰度、包含/排除关键词、单集下限/上限(MB)。留空的维度直接用系统默认(用户默认偏好继承未实现——后端仅提供 `/preference` 存储接口、未接入订阅筛选,页头偏好设置入口未做,当前只在订阅内设置)。
- **资源评分**(自动,「预览」可见打分明细):除新近度/清晰度/盘偏好外,还感知账号与资源形态 —— **百度分享免会员直接加分**;该盘已配置账号加分、**VIP 账号(页头「通知」里勾选)大幅加分**;追更中的订阅遇到 115 分享与「全N集」完结包会减分(它们不会持续更新,完结订阅则不受影响)。

### 2. 查看与播放

- 列表显示进度(`已更新 12/24 集 · 缺第 5-6 集`)、候选源数、下次检查/下集播出时间。
- 「集数」抽屉:每集是否已有、来自主源还是补缺源。
- 「候选源」抽屉:各资源评分/有效性,可手动"启用"换源(换源后播放地址不变,观看进度保留)。
- TVBox 端:订阅配置自动多一个**「我的追剧」内置源**(csp_Media),像逛媒体库一样浏览所有订阅:封面/简介来自绑定的豆瓣/TMDB,支持「全部 / 追更中 / 已完结」分类与按名称搜索;进入剧集后每一集都是**逻辑链接**,播放时后端实时选源(已转存的集优先走你自己的网盘,其次主源分享,再按评分补缺分享),某个源放不了会**自动切换下一个源**,无需手动换源。同一部剧在多个网盘有资源时,详情里还会并列各网盘的**盘线路**(在播放器「线路」里切换,主网盘/已转存的线路排前),线路地址长效注册,进了播放历史也能一直直接播。旧入口(`/tg-search` 首页的「我的追更」分类)仍然可用。

### 3. 一键订阅(不必先建订阅)

- **片单追更**(管理页顶部按钮):浏览豆瓣/TMDB 热门榜单,勾选想追的剧一键预填新建订阅(已订阅过的有标记),不用自己找条目。
- **web 搜索页**(盘搜/电报频道):结果行「追更」按钮 —— 当前资源直接成为主源(订阅即所见)。
- **播放记录页**:历史行「追更」按钮,按剧名订阅。
- **TVBox**:播放 TG 搜索资源时,详情页末尾有「追更」操作组(需 spider.jar ≥ 当前版本),订阅后自动回到第一集继续播。

## 自动转存(多网盘)

选择「自动转存」模式后,可**多选网盘账号**(夸克/115/阿里/UC/百度等任意已配置账号的组合):

- 每小时自动对比源覆盖与各目标网盘已有集,**只增量复制缺失集**;
- **默认仅同盘转存**(源分享盘 == 目标账号盘,服务端保存式,快而稳):夸克分享只进夸克账号、百度分享只进百度账号;跨盘的集不转存、继续走分享播放。需要跨盘时打开「跨网盘转存」开关,或配置 AList 跨盘秒传(`{源}_to_{目标}`,如 `quark_to_123`,允许的方向自动放行);
- 每个网盘独立成败、独立事件记录;**全部目标都失败**才自动降级为挂载模式(追更不中断);
- 每日转存量有上限(默认 20 次,`app.subscription.max-transfers-per-day`),防配额/风控;
- 完结 N 天后自动释放转存文件(默认关闭;「通知」对话框里配 `msub_archive_days`)。

## 追更机制(为什么省心)

- **三级巡检**:优先重新列主源目录发现新集(零搜索开销)→ 主源失效从候选池秒级换源 → 停滞多轮才触发搜索,且无更新自动退避(最长 24h)。
- **缺集补搜**:官方已播而本地缺的集,自动探测候选池并临时挂载验证,覆盖缺口的资源挂为"补缺源",播放列表按集号合并(主源优先);主源日后补齐,补缺源自动退役。
- **候选池**:每次搜索保留 Top 5 有效候选,换源不用现场搜索。
- **4K 升级提醒**:主源非 4K 而池中出现 4K 完整源时提醒(不自动替换,候选源里手动启用)。

## 通知与维护

- **播出时间轴**:页首横条展示**昨天到未来 7 天**每天更新的订阅与媒体播出时间(如 `19:00 凡人修仙传 第188集`),今天高亮;数据来自绑定元数据的分集播出日期,每日随巡检刷新。未绑定元数据的订阅退化为只显示下集播出时间。
- **事件流**:新集/换源/补缺/转存/错误全部记录,列表「动态」抽屉查看;页头「今日/近日更新」收件箱聚合近 3 天。事件自动瘦身:全局保留 90 天,每部订阅保留最近 200 条。
- **Telegram 通知**(可选):页头「通知」里填 Bot Token 与 Chat ID,新集/错误/完结/转存完成会推送。
- **站点搜索源**(页头「通知」内各标签页):除 TG 频道外,追更搜索还接入站点源 —— **玩偶聚合**默认开启、无需配置;**盘链 / 观影 / 蜗牛**需要登录,在各自标签页填站点地址(可选,留空用内置地址/镜像)与账号密码或 Cookie(至少配一样),没配凭证的源自动停用,系统**不内置任何账号**。登录失败会自动冷却几分钟再试,避免连撞风控。
- **网盘范围**(页头「通知」):**全局主网盘**选 1~2 个,巡检优先保证主网盘剧集完整并固定播放线路(订阅里可单独覆盖);**扩展网盘**控制哪些盘的资源能进候选池 —— 不配置时候选/补缺/盘线路只收主网盘的源,主网盘也未配置才不限盘。
- **批量操作**:列表上方「全部状态 / 追更中 / 已完结 / 已暂停 / 异常」下拉筛选,订阅多了快速收敛(全选/批量操作只作用于当前可见行);全选/反选 + 批量检查/暂停/恢复/删除。
- **导出/导入**:JSON 格式,重装迁移或设备间复制(同名同季自动跳过)。

## 常见问题

**Q: 元数据搜索只有豆瓣有结果?**
A: 各源独立性失败会即时提示原因。常见:TMDB 接口在部分网络不可达(可配自备 `tmdb_api_key`);官方平台只返回腾讯本站在播条目;Bangumi 偏动画/日剧。豆瓣始终有本地库兜底。

**Q: 搜索结果封面有的不显示?**
A: 封面已统一走后端 `/images` 代理(TMDB/Bangumi 图床直连可能被墙或防盗链)。仍不显示多为原条目本身无图。

**Q: 夸克分享有效,但其中某一集被和谐了怎么办?**
A: 两种形态都已处理:被和谐的文件从分享列表里**消失**的,巡检直接视为缺集,自动从其他分享补上;文件**还列在目录里但实际取不了**的(点开播放失败),由**新集预热验证**兜底 —— 巡检发现新集时会对该集做链接解析探测,失败的集立即登记为"源损坏"(7 天过期自动重试),当轮就从其他分享补源;自动转存模式下转存校验也会发现同样问题。集数清单中这类集显示「源损坏(待补源)」。预热探测每轮上限 5 集(`app.subscription.preheat-max-per-round`),可用 `app.subscription.preheat-enabled` 关闭。

**Q: 元数据接口失败会一直重试吗?**
A: 不会。各元数据源带熔断器:连续失败 3 次短路 60 秒,期间跳过该源(搜索页会提示),成功一次即复位。

**Q: 目录名里的 `[dbid-x]` / `[tmdbid-x]` / `[bgmid-x]` 是什么?**
A: 绑定元数据后,订阅目录与转存目录会带上豆瓣/TMDB/Bangumi 的条目 id:全局唯一(同名剧/不同剧不怕撞名),Emby/Jellyfin/tinyMediaManager 等刮削器也能按 id 精准匹配元数据。仅对新建订阅生效(存量订阅目录不改名,固定路径不动);转存目录若为旧命名,下次转存时会自动原地改名迁移,不重复拷贝。

**Q: 每一集可以来自不同网盘的分享吗?**
A: 可以,这正是缺集补搜 + 多源合并的形态:第 1 集来自夸克分享 A、第 2 集来自夸克分享 B、第 3 集来自百度分享,播放列表按集号合并成单一入口,你感知不到背后有几个分享。分享直连播放**不需要**网盘账号;若想彻底免疫分享失效,选自动转存模式并配置网盘账号 —— 已转存的集会**优先从你自己的网盘播放**(逐集生效:哪集转好了走哪集,没转好的继续走分享),跨盘复制由内嵌 AList 完成(夸克分享 → 百度盘也可以)。

**Q: 为什么出现了 `/追剧/xxx-补1`、`-补2` 这样的挂载?**
A: 旧版本的补缺源曾与主源并排展示;现在补缺源统一收纳在内部目录 `/追剧/.sources/` 下 —— **`/追剧/` 里每部剧只有一个文件夹入口**,多个分享资源在播放列表里按集号自动合并(主源优先),你不需要关心背后有几个分享。旧挂载会在下轮巡检自动迁移。主源日后补齐对应集数后,补缺挂载自动退役删除;每订阅最多 3 个补缺挂载(`app.subscription.max-gap-mounts`)。

**Q: 换源会丢观看进度吗?**
A: 不会。订阅固定挂载路径,换源只替换路径背后的分享,播放地址与历史记录不变。「我的追剧」源里更进一步:每集用的是逻辑链接(`msubep-订阅-集号`),换源/补缺源切换完全无感,续看进度也绑定在逻辑链接上。

**Q: 单集上限怎么配?**
A: 新建/编辑订阅的筛选条件里「单集上限(MB)」,0 为不限;超限文件不计入集数、不转存(用于过滤捆绑包/花絮合集里的异常大文件)。

**Q: 转存目标支持哪些网盘?**
A: 任意已在「账号」页配置的 DriverAccount 均可,且可多选同时转存;跨盘复制由内嵌 AList 完成,源(分享)与目标(账号盘)类型不必相同。

**Q: 最多可以订阅多少部剧?**
A: 没有数量上限,真正的约束是巡检吞吐:巡检每小时一轮、每轮最多处理 30 个到期订阅(`app.subscription.max-checks-per-round`)、并发 4 个(`app.subscription.check-concurrency`)。按每部剧 6~12 小时检查一次估算,活跃追更的订阅 **150 个左右以内**新集发现延迟稳定在小时级(100+ 部是设计覆盖规模);再多到期订阅会排队、发现变慢,可调大上面两个参数,但网盘与搜索源的压力会同步上升。已完结的订阅几乎零成本:看完的完结剧每周一次轻量复查(只刷元数据,不列源不搜索),近 7 天仍在追看的完结剧每日照跑完整巡检(换源/补缺照常,见下条)。

**Q: 已完结的剧,分享失效了还会被发现吗?**
A: 会。近 7 天有播放记录且还没看完的完结剧,每日照常跑完整巡检,失效换源、缺集补搜与追更中完全一致;看完或超过 7 天没看的完结剧才降为每周轻查 —— 这类剧如果点播时全部候选都放不了,会立即自动重开一轮完整巡检自愈(换源或补搜),资源恢复后自动回到完结状态,不需要手动干预。

**Q: 同一部剧想同时追好几个季?**
A: 每季建一个订阅即可。同一 TMDB 条目的多季挂载路径会自动区分 —— 第 2 季起目录名追加「 S02」这样的后缀,互不覆盖(豆瓣按季分条目,天然不冲突;仅对新建订阅生效)。注意在「编辑」里直接修改季号是**整体重置**:旧季的挂载、候选资源与观看进度会清空,按新季重搜重挂(保存前有确认提示);想保留旧季进度就另建一个新订阅。
